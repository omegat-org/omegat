# Unified Presentation and Accessibility

## Status
**Draft / Proposal** — skeleton, to be refined alongside the work.

## Date
2026-08-01

## Context

- Segment state is signalled by colour only; colours are configurable, formatting is not,
  non-visual channels do not exist.
- Open tickets point the same way: RFE-1553 (VoiceOver), RFE-869 (audio hints),
  RFE-1576 (subtitling), RFE-1321 (per-line counts).
- Swing Accessibility API is essentially unused; no a11y guideline in the docs.

## Proposal

Maybe treat colours, formatting, audio/speech, and accessibility as one presentation layer,
configured in one place in the GUI. Possible stages, each shippable on its own:

1. **Colours** — started (colour table, theme import/export, live refresh).
2. **Formatting** — bold/italic/strikethrough per marker category, next to its colour.
3. **Audio/speech** — beeps for events, perhaps TTS/voice for segments.
4. **Subtitles + video** — subtitle block with synced video (RFE-1576), building on 2–3.

Baseline in any case: wire up the Swing Accessibility API (names/descriptions for icon-only
controls, panes, fields).

## Input from affected-user perspectives (2026-08)

Condensed findings from a persona review (blind, low-vision, deaf/sign-language,
motor-impaired translators); to be validated against real users.

- No channel exclusive: information never colour-only, sound-only, or mouse-only.
  Suggests an event abstraction with several output channels (sound, flash,
  notification history) rather than isolated beep features.
- Non-focusable controls only with an equivalent (menu entry / shortcut);
  applies to the pane settings (gear) menu.
- The active segment is the hotspot: announce it (status, match, glossary hits),
  make it more visible (frame, caret), return focus to it predictably.
- Named small wins: pane focus shortcuts, editor zoom via Ctrl+wheel, dialog
  hygiene (Escape/default button), progress queryable via shortcut.
- Medium: announce on segment change; formatting per marker category;
  contrast audit + high-contrast preset; timecodes and CPS checks in subtitle filters.
- Probably not worth pursuing: built-in TTS as a screen-reader substitute;
  sign-language avatars/recognition. Glossary entries linked to sign videos may be.

## Open questions

- Where exactly in preferences; how much shared UI between stages.
- Style model beyond `Color` for markers; TTS/video dependencies (plugin vs. core).
