# Unified Presentation and Accessibility

## Status
**Draft / Proposal** — skeleton, to be refined alongside the work.

## Date
2026-08-01

## Context

- Segment state is signalled by colour only; colours are configurable, formatting is not,
  non-visual channels do not exist.
- Open tickets point the same way: RFE-1553 (VoiceOver), RFE-869 (audio hints),
  RFE-1576 (subtitling), RFE-1321 (per-line counts).
- Swing Accessibility API is essentially unused; no a11y guideline in the docs.

## Proposal

Maybe treat colours, formatting, audio/speech, and accessibility as one presentation layer,
configured in one place in the GUI. Possible stages, each shippable on its own:

1. **Colours** — started (colour table, theme import/export, live refresh).
2. **Formatting** — bold/italic/strikethrough per marker category, next to its colour.
3. **Audio/speech** — beeps for events, perhaps TTS/voice for segments.
4. **Subtitles + video** — subtitle block with synced video (RFE-1576), building on 2–3.

Baseline in any case: wire up the Swing Accessibility API (names/descriptions for icon-only
controls, panes, fields).

## Open questions

- Where exactly in preferences; how much shared UI between stages.
- Style model beyond `Color` for markers; TTS/video dependencies (plugin vs. core).
