# ADR: Color Binding Primitive and Plugin Color Contributions

## Status
**Proposed**

## Context

Colors-changed broadcast (`CoreEvents.fireColorsChanged`) made color changes
live — but only for panes opting in by hand: register listener, re-apply,
repaint. Nothing enforced this; new panes silently shipped without live
refresh, and almost none unregistered (each search window leaked one
listener). Palette itself was closed enum `Styles.EditorColor`: plugins
could not surface own colors in preferences table or scheme export/import.

## Decision

1. **Binding primitive.** `Styles.bindColors(JComponent[, Runnable])`
   replaces manual triple: applies colors immediately, registers with
   `CoreEvents` while component is displayable, unregisters otherwise
   (tracked via `HierarchyListener`), re-applies on re-registration.
   Swing thread or single-threaded startup. Editor-cluster panes still
   registering by hand convert once pending changes merge.
2. **Contribution SPI.** Extension point `ColorEntry` (id, display name,
   effective color, default, persisting setter); `Styles.EditorColor`
   implements it, constant names double as stable ids. Plugins register at
   load time via `ColorRegistry.registerPluginColor(...)`, namespaced
   `pluginId:colorKey`. Preferences table snapshots `ColorRegistry.all()`
   at construction; scheme export/import and defaults iterate live.
   Unknown ids in imported schemes are skipped.
3. **Shared semantics.** Plugin entries persist under `pluginId.colorKey`
   (preference keys are XML element names — `:` forbidden), resolve defaults
   via UIManager key plus fallback, reset on `null`/default — like
   `EditorColor` (see [ADR 2026004](2026004.EditorColorRegistryConsistency.md)).
   Stored override resolves lazily on first `getColor()` after
   `Preferences.init()` — plugins load earlier.

## Consequences

- One line binds any pane; short-lived components stop leaking listeners.
- Re-apply fires on every re-dock even without palette change; heavy
  appliers (e.g. table rebuild) pay per docking cycle.
- Plugin colors appear in preferences and exported schemes without core
  changes per plugin.
- Entries live for session, cannot unregister; plugin ids must stay stable
  or user overrides and schemes lose binding.
